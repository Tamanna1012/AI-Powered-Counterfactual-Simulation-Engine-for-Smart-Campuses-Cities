## 1. Install prerequisites
* A C++17 compiler with OpenMP (g++ 9 or newer; the project was built and tested with **g++ 13.3 on Ubuntu Linux**).
* GNU make, Python 3.9+, and `pip install -r requirements.txt` (pandas, numpy, matplotlib, python-docx, pygments).
* **Linux / WSL2 (recommended on Windows):** `sudo apt install g++ make python3 python3-pip`.
  WSL2 setup: in an administrator PowerShell run `wsl --install`, restart, open "Ubuntu". Your Windows drive is at `/mnt/c/...`.
* **Native Windows (untested by the authors of this package):** install MSYS2 (https://www.msys2.org), open the *UCRT64* shell, run
  `pacman -S mingw-w64-ucrt-x86_64-gcc make python python-pip`. MSVC is not supported (its OpenMP is 2.0 and `bfs_tests.cpp` uses `dirent.h`).
* macOS: `brew install gcc`, then `CXX=g++-14 make`.

## 2. Compile the sequential BFS and 3. the OpenMP BFS
```bash
make                      # builds bin/bfs_seq, bin/bfs_par and bin/bfs_tests with: g++ -O3 -std=c++17 -fopenmp -Wall -Wextra
```
Without `make` (for example in a plain MinGW shell):
```bash
mkdir bin
g++ -O3 -std=c++17 -fopenmp -I. -I../02_Lucky_Sequential_BFS -I../03_Girlfriend_OpenMP_BFS ../02_Lucky_Sequential_BFS/bfs_seq_main.cpp   -o bin/bfs_seq
g++ -O3 -std=c++17 -fopenmp -I. -I../02_Lucky_Sequential_BFS -I../03_Girlfriend_OpenMP_BFS ../03_Girlfriend_OpenMP_BFS/bfs_par_main.cpp  -o bin/bfs_par
g++ -O3 -std=c++17 -fopenmp -I. -I../02_Lucky_Sequential_BFS -I../03_Girlfriend_OpenMP_BFS bfs_tests.cpp                                  -o bin/bfs_tests
```
Run one benchmark by hand (`--help` lists all options):
```bash
bin/bfs_seq --graph random --n 262144 --deg 16 --reps 7
bin/bfs_par --graph random --n 262144 --deg 16 --threads 1,2,4 --schedule dynamic --chunk 64 --reps 7
```

## 4. Run the correctness tests
```bash
make test            # same as: bin/bfs_tests tests/cases
```
Part 1 checks the 12 hand-made graphs in `tests/cases` (path, star, cycle, grid, complete, tree, disconnected, isolated source, single vertex,
duplicate edges + self-loop, two routes of different length). Part 2 compares parallel and sequential BFS on generated path/grid/random/R-MAT/disconnected graphs
for 1, 2, 4, 7 threads and static/dynamic/guided schedules, repeated to expose races, and runs an independent validator. Expected last line:
`1402 checks passed, 0 failed` (our captured output: `logs/correctness_test_output.txt`).

## 5. Run the experiments
```bash
python3 scripts/run_experiments.py --quick --out quick_test.csv      # 1-minute smoke test (does not touch data/raw/bfs_raw.csv; delete quick_test.csv afterwards)
python3 scripts/run_experiments.py --fresh --student1-id <RegNo1> --student2-id <RegNo2> --batch-id <Batch> --note "laptop, plugged in"
```
The full run takes roughly 10-20 minutes on 4 cores (the 1M-vertex path graph is the slowest). The runner pins threads (`OMP_PROC_BIND=true`, `OMP_PLACES=cores`),
records CPU/RAM/OS/compiler to `data/env/environment.json`, and refuses to overwrite an existing raw CSV unless `--fresh` is given.
Close other programs, plug in the laptop, and keep thread counts <= the number of logical CPUs (the runner picks 1, 2, 4, ... automatically).

## Conventions shared by both implementations
* Graph: undirected, simple, CSR adjacency list, 32-bit vertex ids; identical code builds it for both programs (`Graph_Checksum` column proves it).
* Start vertex: vertex 0 for path/grid; the lowest-index maximum-degree vertex for random/R-MAT.
* **Timed region** = one call to `bfs_seq()` / `bfs_par()` (includes its own array initialisation; for the parallel version also thread start-up and the final copy). Graph generation, validation and statistics are not timed. Clock: `std::chrono::steady_clock`, seconds.
* Speedup = median sequential time / median parallel time (same graph); efficiency = speedup / threads; TEPS = undirected edges in the reached component / time (Graph500 convention).
* `Synchronization_Time` = per level (slowest thread's expand time - mean expand time), summed; `Frontier_Merge_Time` = wall time of the merge phase. Both come from an extra instrumented run, never from the timed run. `Scheduling_Time`, `Communication_Time`, `Energy_if_available` = NA.
* Raw CSV has all columns required by the manual (Student_ID ... Run_ID; Speedup/Efficiency left empty on purpose) plus extra columns.

## Known gaps (documented, not hidden)
* No GPU/CUDA version (no GPU available). No SNAP/SuiteSparse downloads (synthetic Graph500-style graphs only; `--graph file --file X` accepts a simple edge list, see `graph.hpp`).
* Measurements come from one 4-vCPU cloud VM, 1/2/4 threads only. No direction-optimizing BFS, no energy measurements.
* Names, registration numbers and batch ID are placeholders; some reference DOIs/volumes still need to be confirmed (`REFERENCES.md`).
